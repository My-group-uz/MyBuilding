# MyBuilding

Учёт бюджета, прихода и расхода по строительным объектам.
Мультиарендное приложение: каждая организация видит только свои данные.

## Стек

FastAPI + PostgreSQL (asyncpg), фронтенд без сборки — статические
HTML/CSS/JS. Внешних сетевых зависимостей нет: шрифт Onest и все иконки
лежат локально, приложение работает без интернета.

## Запуск на Railway

1. Создать проект из этого репозитория.
2. Добавить плагин **PostgreSQL** — Railway сам подставит `DATABASE_URL`.
3. Задать переменные окружения (раздел Variables):

| Переменная | Обязательна | Назначение |
|---|---|---|
| `DATABASE_URL` | да | Подставляется плагином PostgreSQL |
| `SECRET_KEY` | да | Ключ подписи сессионных кук, произвольная длинная строка |
| `COOKIE_SECURE` | да | `1` — кука только по HTTPS |
| `SUPERADMIN_LOGIN` | нет | По умолчанию `994067406` |
| `SUPERADMIN_PASSWORD` | нет | По умолчанию `7406` |
| `GOOGLE_CLIENT_ID` | нет | Проще настроить в админке |
| `GOOGLE_CLIENT_SECRET` | нет | Проще настроить в админке |
| `UPLOAD_DIR` | нет | Определяется автоматически по Volume |
| `RAILWAY_VOLUME_MOUNT_PATH` | — | Подставляется Railway при подключении диска |

> **`SECRET_KEY` обязателен.** Без него ключ генерируется при старте, и
> после каждого деплоя или перезапуска все пользователи разлогиниваются.

> **`COOKIE_SECURE=1` на проде.** Иначе сессионная кука уйдёт по
> незашифрованному соединению.

Схема БД создаётся и мигрирует автоматически при старте — отдельный шаг
миграции не нужен.

### Вход через Google

Настраивается **прямо в админке**, без переменных окружения и
передеплоя: раздел «Вход через Google» внизу страницы организаций.

1. Открыть админку → «Вход через Google» → скопировать **адрес возврата**
   (он подставляется автоматически под текущий домен).
2. Google Cloud Console → APIs & Services → Credentials →
   **Create OAuth client ID**, тип **Web application**.
3. Вставить скопированный адрес в **Authorized redirect URIs**.
4. Полученные Client ID и Client secret вписать в форму админки.

Кнопка на странице входа появится сама. Пока ключей нет — её просто не
видно, вход по паролю работает.

Переменные `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` тоже поддерживаются
и имеют приоритет; если они заданы, форма в админке блокируется, чтобы
правки не пропадали молча.

Самостоятельная регистрация через Google отключена: войти может только
почта, уже заведённая администратором. Иначе арендаторы создавались бы
в обход админки.

### Постоянное хранилище файлов

**Файловая система Railway эфемерна** — при каждом деплое контейнер
пересоздаётся, и всё загруженное пропадает. Нужен Volume:

1. Railway → сервис → вкладка **Variables** → **+ New Volume**
2. Mount path указать любой, например `/data`
3. Передеплой — больше ничего делать не нужно

Railway при подключённом диске сам подставляет переменную
`RAILWAY_VOLUME_MOUNT_PATH`, а приложение её читает и начинает писать
в `<точка монтирования>/uploads`. Правок в коде и переменных не требуется.

Проверить, что диск подхватился, можно на `/health`:

```json
"storage": { "path": "/data/uploads", "persistent": true, "source": "railway-volume" }
```

`"persistent": false` означает, что файлы пропадут при следующем деплое.

Каталог можно задать и вручную переменной `UPLOAD_DIR` — она имеет
приоритет над автоопределением.

### Диагностика после деплоя

`GET /health` показывает, дошли ли настройки до приложения:

```json
{
  "status": "ok",
  "database": true,
  "storage": { "persistent": true, "source": "railway-volume" },
  "google_auth": true,
  "secret_key_set": true,
  "cookie_secure": true
}
```

Если `secret_key_set` или `cookie_secure` равны `false` — переменные
не заданы, см. таблицу выше.

## Локальный запуск

```bash
python -m venv .venv
.venv/Scripts/activate           # Windows
pip install -r requirements.txt

export DATABASE_URL="postgresql://postgres:пароль@127.0.0.1:5432/mybuilding"
export SECRET_KEY="любая-строка-для-разработки"

uvicorn main:app --reload
```

Открыть <http://127.0.0.1:8000/> — откроется страница входа.

## Роли

**Суперадминистратор** (`/frontend/admin.html`) — заводит организации:
название, ФИО, телефон, почта, пароль, логотип, статус. К данным
арендаторов доступа не имеет.

**Организация** (`/frontend/index.html`) — работает со своими объектами:
Аналитика, Приход, Бюджет, Расход, Настройки.

## Изоляция данных

Проверка вынесена в middleware `tenant_guard` (main.py), а не расставлена
по обработчикам: маршрутов почти три десятка, и один забытый превратился
бы в утечку. По идентификатору из пути определяется организация-владелец
и сверяется с сессией. Чужие сущности отдают **404**, а не 403 — иначе
перебором id можно было бы выяснить, что существует у других.

## Структура

```
main.py          точка входа, объекты, приход, middleware изоляции
auth.py          пароли, сессии, разрешение владельца
auth_api.py      вход, Google OAuth, CRUD организаций
db.py            схема, миграции, индексы, ограничения
budget_api.py    бюджет: этапы → виды работ → ресурсы
expense_api.py   расход: факт по ресурсам, чеки
frontend/        статика без сборки
```
